1. Abstract

This study asks whether observed content and performance signals can help identify content that may be declining and therefore deserves human review. Using the FlyRank ML Internship anonymized content dataset, a binary decline label was constructed from the observed trend direction and a Random Forest classifier was evaluated using a client-grouped train/test split. The model used available numeric and categorical content, search, engagement, freshness, and traffic-related signals while excluding direct identifiers and the fields used to define the outcome. On the held-out grouped test set, the measured Precision@50 was 1.00, compared with the recorded baseline Precision@50 of 0.24. This result is treated as an observed, dataset-specific decision-support result rather than evidence of guaranteed future performance.

2. Introduction / Problem Statement

Content teams often manage large collections of pages and cannot manually inspect every page with equal priority. A useful operational question is therefore whether available performance and content signals can help create a smaller review queue.

The research question for this project is:

Can observed content and performance signals help identify content that may be declining?

The intended decision is not automatic content removal or automatic ranking changes. Instead, the model is intended to help prioritize content for human review and possible refresh.

3. Data

The analysis uses the anonymized content-refresh dataset provided as part of the FlyRank ML Internship work.

  • Rows analysed: approximately 30,000 content records
  • Features available before modelling: 45 columns
  • Clients represented: 32 anonymized clients
  • Keyword articles: 27,207
  • Feedly articles: 2,096
  • Comparison articles: 697

The target was constructed as:

is_declining_label = (trend_direction == "down")

The resulting target distribution contained 16,262 records labelled as declining and 13,738 records labelled as not declining.

Public-safety handling

Direct identifiers such as client and content identifiers were excluded from the modelling features. Fields used to construct the outcome label were also excluded from the final feature set.

No client names, private search queries, private URLs, domains, titles, or other private identifying information are presented in this paper.

4. Methodology

Validation strategy

A GroupShuffleSplit was used with clients as the grouping variable. The test size was 20% and the random seed was 42.

The resulting split contained:

  • Training records: 23,837
  • Test records: 6,163
  • Client overlap between training and test: 0

Grouping by client was used to reduce the risk that records from the same client would appear in both training and test sets.

Model

The main model was a Random Forest classifier with:

  • 300 trees
  • Random state: 42
  • Balanced class weights
  • Parallel processing enabled

Numeric features were median-imputed. Categorical features were imputed using the most frequent value and one-hot encoded with unknown categories ignored during transformation.

Feature groups

The model used available signals describing areas such as content characteristics, search performance, engagement, freshness, and traffic. Direct identifiers and outcome-defining fields were excluded.

Evaluation metric

The primary evaluation metric is Precision@50. It measures the proportion of the 50 highest-ranked records that belong to the decline class.

On the held-out client-grouped test set, the Random Forest ranked 50 records at the top of the queue and all 50 belonged to the observed decline class.

Important interpretation: A Precision@50 of 1.00 is an observed result for this particular dataset, feature construction, model, and validation split. It should not be interpreted as a guarantee that the same precision will occur on future unseen production data.

Operational interpretation

The result suggests that the available signals contain substantial information about the observed decline label. The model can therefore be considered as a prioritization mechanism for a human review queue.

6. Limitations & Honest Framing

  • The result is measured on one held-out grouped split and may not generalize to future datasets.
  • The study identifies records associated with an observed decline label; it does not establish causality.
  • The model should not be interpreted as predicting or reproducing a search engine's ranking algorithm.
  • The unusually high measured Precision@50 should be investigated further before treating it as a production-ready performance estimate.
  • Potential feature overlap, label construction effects, and differences between retrospective identification and genuine future prediction should be tested in a future iteration.
  • Model output is intended as directional decision-support and should be reviewed by humans before content changes are made.

7. Ranked Recommendations

The model output can be converted into a ranked review queue using the predicted probability of decline.

  1. Review the highest-scoring content first. Use the model score to prioritize a manageable review queue.
  2. Investigate freshness. Older content and content that has not been updated recently can be candidates for editorial review.
  3. Review engagement performance. Low engagement can provide additional context when deciding whether a page requires improvement.
  4. Inspect observed performance trends. Historical performance changes can help reviewers understand why a record entered the review queue.
  5. Keep humans in the loop. Model scores should support editorial decisions rather than automatically trigger content changes.
