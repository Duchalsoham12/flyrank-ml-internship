1. Abstract

This study investigates whether safe search-performance and content signals can be used to rank pages that deserve human review for possible decline, recovery, or improvement. Using 30,000 anonymized content records from the FlyRank ML Internship dataset, a binary decline label was constructed from the observed trend direction and evaluated using a client-grouped validation strategy. A Random Forest classifier was compared with a simple trend-based baseline using Precision@50 as the primary ranking metric. Both approaches achieved a Precision@50 of 1.000 on the held-out test set, while the Random Forest achieved an overall classification accuracy of 0.801. The results indicate that the available signals contain useful information for decision-support, but the identical top-50 ranking performance means the model cannot be claimed to outperform the simple baseline on this split.

2. Introduction / Problem Statement

Content teams often manage large collections of pages and cannot manually inspect every page with equal priority. A useful operational question is therefore whether available performance and content signals can help create a smaller review queue.

The research question for this project is:

Can safe search-performance signals be used to rank pages that deserve review for decline, recovery, or improvement?

The intended use is decision support rather than automatic content modification. The model can help prioritize pages for human investigation, while final decisions remain with content and SEO reviewers.

3. Data

The analysis uses the anonymized content-refresh starter dataset provided as part of the FlyRank ML Internship work. The final modelling input was the file content_refresh_anonymized.csv.

  • Total records analysed: 30,000
  • Features used for modelling: 40
  • Training records: 23,837
  • Testing records: 6,163
  • Training clients: 25
  • Testing clients: 7

The target label was constructed from the observed trend direction:

is_declining_label = (trend_direction == "down")

The following fields were excluded from model features: content_id, client_id, trend_direction, trend_pct, and is_declining_label. The trend fields were excluded because trend_direction was used to construct the target label, while identifiers were excluded to avoid using direct identifiers as predictive features.

The final 30,000-row starter dataset was used directly for modelling. The larger FlyRank warehouse was not used as the direct modelling input for this capstone experiment.

Public-safety handling

Direct identifiers such as client and content identifiers were excluded from the modelling features. The trend fields used to construct the outcome were also excluded from the model features to reduce direct target leakage.

No client names, private search queries, private URLs, domains, credentials, or other private identifying information are presented in this paper.

4. Methodology

Validation strategy

A GroupShuffleSplit was used with clients as the grouping variable. The test size was 20% and the random seed was 42.

The final split contained:

  • Training records: 23,837
  • Test records: 6,163
  • Training clients: 25
  • Test clients: 7
  • Client overlap: 0

The zero client overlap is important because it reduces the risk of the model being evaluated on records from clients it effectively saw during training.

Baseline

A simple trend-based baseline ranked test records using the observed negative trend magnitude. This provides a straightforward benchmark against which the machine-learning model can be compared.

Random Forest model

The main model was a Random Forest classifier configured with:

  • 300 trees
  • Random state: 42
  • Balanced class weights
  • Parallel processing enabled

Numeric features were median-imputed. Categorical features were imputed using the most frequent value and one-hot encoded. Unknown categories were ignored during transformation.

Evaluation metric

Precision@50 was used as the primary ranking metric. It represents the proportion of the 50 highest-ranked records that belong to the observed decline class.

6. Limitations & Honest Framing

  • The evaluation uses one client-grouped train/test split and may not generalize to future data.
  • The decline label represents an observed trend condition and does not establish why the decline occurred.
  • The model does not predict or reproduce a search engine's ranking algorithm.
  • Precision@50 is saturated at 1.000 for both approaches on this test split, so additional validation is needed before treating the result as a strong production performance estimate.
  • Feature importance indicates model usage patterns, not causal relationships.
  • The ranked queue is intended for human review and should not automatically trigger content changes.

7. Ranked Recommendations

The model output can be converted into a ranked action queue using predicted decline probability together with transparent heuristic reason codes.

  1. Review the highest-priority pages first. Use the ranked score to reduce a large content collection to a manageable review queue.
  2. Check content freshness. Pages that have not been updated for a long period can be reviewed for outdated information or missing improvements.
  3. Investigate negative performance trends. Review recent search-performance changes before deciding on an action.
  4. Review engagement signals. Low engagement can provide additional context for editorial investigation.
  5. Keep humans in the loop. Reviewers should inspect the page and business context before making refresh, improvement, or recovery decisions.

Suggested action categories

Signal Suggested action
Stale content + negative trend Refresh content
Low engagement + negative trend Review intent and refresh
Low engagement Review content quality
Negative trend Investigate decline
Other high-priority cases Human review
